# Spec: P2 Opponent and Match

Nov 19, 2026 · @Khiem · Rewritten after a design review against the repo, `GLOSSARY.md` and ADRs 0001–0002. This file is the source of truth; the draft `Spec-P2-AI-opponent-and-match.md` and any Claude Docs copy are superseded.

## How to use this spec

This spec takes the game from Return Drill alone to a second mode, **Match**: an 11-point Game (or best of three) against a computer **Opponent** with three Difficulties. Return Drill stays as the practice mode and the path through onboarding. There are eleven seams; each is one Claude Code session, one GitHub issue and one pull request. Start each session with:

```
Read docs/specs/p2.md, CLAUDE.md, GLOSSARY.md and docs/adr/. Implement seam <ID> only.
First propose a plan that lists every file you will create or change,
maps it to the seam's Owns list, and names the tests you will write.
Wait for my OK before writing code.
```

**Order**

1. P2-0 (headless core). Merge before anything else.
2. P2-b (Rally engine), P2-e (Match rules) and P2-g1 (play log) in parallel, separate git worktrees.
3. P2-c (Opponent brain) after P2-b.
4. P2-d (Opponent body) after P2-c; P2-f1 (Opponent Serves and scoring) after P2-c and P2-e. These two can run in parallel.
5. P2-f2 (player Serve) and P2-h1 (Match HUD) after P2-f1.
6. P2-g2 (balance harness) after P2-f2 and P2-g1; P2-h2 (start and Game-over screens) after P2-f2 and P2-h1.

There is no P2-a: Lift → Topspin and answering spin shipped in P1-e2 and P1-e3, and chop → Backspin is on the Later list.

## Project context

**Already built** (S0 and P1 are merged; details in `docs/specs/s0-p1.md`): Return Drill, where the **Feeder** sends **Feeds** and the player returns them by swinging at the webcam. A Swing comes from a `SwingSource` as a `SwingEvent` at its Onset; the shot resolver accepts it inside the Hit Window around the Feed's Ideal Time and plans a Return from timing, speed and Lift (`planReturn`); `solveShot` turns a `ShotIntent` into a launch velocity and spin. Outcomes come from timing, never Paddle–ball contact (ADR 0001). Spin, the spin-aware bounce and the Net-cord are in `src/physics/`. All randomness comes from one `makeRng(seed)` (`?seed=<n>` replays a session).

**Words**: use `GLOSSARY.md` in code, comments and tests: Opponent (never AI, CPU or bot), Feeder, Feed, Serve, Shot, Return, Rally, Point, Game, Match, Difficulty, Rally End (Net, Out, Own-half, Unreturned), Pop-up, Error, Whiff, Fault, Let, Net-cord, Lift.

**Invariants** (as in S0/P1, plus)

- Units: meters, seconds, rad/s inside; rev/s in knobs, tables and readouts, converted at the edge with `revsToRadPerSec`.
- Frame: origin on the floor under the table centre, y up, +z toward the player, net at z = 0, table top at y = 0.76 m. The player's end line is `PLAYER_END_Z` (+1.37 m), the Opponent's `OPPONENT_END_Z` (−1.37 m). The Opponent and, in Return Drill, the Feeder stand at the −z end.
- Clock: real time is `performance.now()` ms, passed in as `nowMs`; simulated time runs at `TIME_SCALE` (0.8) and fixed `PHYSICS_DT` = 1/240 s substeps. Opponent flight times, reactions and body motion are in simulated seconds, so they slow with the ball.
- Randomness: only the injected `random: () => number`. No `Math.random()` or `Date.now()` in `src/game/`, `src/physics/` or `src/opponent/`.
- Headless: `src/game/`, `src/physics/` and `src/opponent/` never import `three`, `@mediapipe/*` or `src/render/` (type-only imports from `src/sensing/` are allowed). The whole game runs in Node.
- ADR 0001: a Shot's outcome is decided by moving its target, never by adding noise to its launch. ADR 0002: the Opponent's brain decides each Shot at launch; its body is cosmetic.
- Tuning guesses are knobs, except Difficulty values: `DIFFICULTIES` is a plain table (3 × 9 values), tuned offline with P2-g2, not by sliders mid-rally.

**Rules for every session**

1. Change only files in the seam's Owns list. If something else must change, stop and ask.
2. Don't add dependencies.
3. For pure modules, write the tests first.
4. Before saying done, run `npm test`, `npm run typecheck` and `npm run build`, and list anything you could not verify yourself.

**Numbers in this spec** (Difficulty values, weights, thresholds) are starting guesses to be tuned with P2-g2 and playtests, not measured values.

## P2-b Rally engine

**Goal**: turn the one-way drill into a two-way Rally. Any Shot heading to either side gets an Ideal Time; the receiver (player or Opponent) gets a chance to return it; the Rally ends with the right Rally End and loser. Until P2-c, a scripted Opponent returns everything to the middle; until P2-f1, each Rally starts with a Feed.

**Owns**: `src/game/rally.ts` and test, `src/opponent/scripted.ts`, `src/game/shotResolver.ts` and test, `src/game/feeder.ts` (use the moved `findIdealTime`), `src/game/core.ts` and test, `src/game/constants.ts` (`SPIN_ANSWER_FULL_REVS`), `src/main.ts` (`?mode=match` flag only).

**Depends on**: P2-0. Can run in parallel with P2-e.

**Contract** (`src/game/rally.ts`)

```ts
export interface IdealTime { simSeconds: number; position: Vec3 }   // moved from feeder.ts
/** When the Shot's centre crosses the receiver's end line after bouncing on the receiver's half; null if it never does. */
export function findIdealTime(ball: BallState, receiver: Side): IdealTime | null;

export interface Incoming {             // what a receiver needs to decide
  readonly receiver: Side;
  readonly ball: BallState;             // the Shot at launch
  readonly launchedAtMs: number;
  readonly ideal: IdealTime;
  readonly idealAtMs: number;           // Ideal Time on the performance.now() clock
  readonly strike: BallState;           // the ball at the Ideal Time (position, velocity, spin)
  readonly shotIndex: number;           // 0 = the Rally's first Shot
}
export type RallyEnd = 'net' | 'out' | 'own-half' | 'unreturned';
export type RallyEvent =
  | { type: 'shot'; atMs: number; by: Side; shotIndex: number }
  | { type: 'bounce'; atMs: number; half: Side }
  | { type: 'end'; atMs: number; end: RallyEnd; loser: Side };
export interface Opponent {
  /** Called when a Shot toward the Opponent launches (ADR 0002); applied at the Ideal Time. */
  chooseShot(incoming: Incoming, random: () => number): ShotIntent | 'whiff';
}
/** Pure referee: fed each Shot's launch and the ball's events, it returns the Rally End once there is one. */
export function createReferee(): Referee;
```

**Rules the referee enforces** (Rally End is in `GLOSSARY.md`)

- After a Shot by the hitter, its first bounce must be on the receiver's half. A dead net → `net`; off the table with no bounce → `out`; first bounce on the hitter's half → `own-half`. All lose the Point for the hitter.
- After that bounce, the receiver must make a Return before a second bounce. A second bounce, or the ball leaving the table, → `unreturned`, against the receiver. No volleys: a Swing before the bounce is Early.
- A Net-cord plays on (the ball's `cord` event).
- An Opponent Whiff, or a player Early, Late or Miss, launches nothing: the ball flies on and the referee ends the Rally as `unreturned`.

**Implementation notes**

- When any Shot launches, simulate it ahead once (`findIdealTime`) to build the receiver's `Incoming`.
- Player side: the resolver's `startFeed(feed: FeedTiming)` becomes `startIncoming(incoming: IncomingTiming)` (same fields: `idealAtMs`, `topspin`); the Feeder calls it too. Contact at `max(now, idealAtMs)` as today.
- Spin answer: P1-e3 scales the incoming Topspin against `FEED_SPIN_MAX_REVS`. Replace that with a fixed constant `SPIN_ANSWER_FULL_REVS = 40` in the resolver (so Return Drill is unchanged at default knobs). Spin above it counts as full.
- Opponent side: at the launch of a Shot toward the Opponent, call `opponent.chooseShot`. At `idealAtMs`, strike from `contactPoint(ball.position)` with `solveReturn`, drawing the Shot's seed from `random`. On `'whiff'`, do nothing.
- `scripted.ts`: always returns to (x 0, z 0.7), 0.9 s flight, no spin.
- Rally start: in Match mode, after `FEED_PAUSE_S` and the "3, 2, 1" cue, the Feeder launches a Feed as the Rally's Shot 0 (stand-in for the Serve until P2-f1).
- `core.ts` gains a mode (`'drill' | 'match'`) and `onRally(listener)` for `RallyEvent`s. `main.ts` picks the mode from `?mode=match`; Return Drill is the default.

**Done (Claude checks)**

- [ ] Referee tests build real balls (`launchBall` + `simulate`) for each Rally End, both directions, and assert the end and loser; a Net-cord that lands legally plays on
- [ ] `findIdealTime` for a Shot and its mirror image (z flipped) give the same time and mirrored position, within 1 ms and 1 mm
- [ ] Headless: a scripted player (swings at `idealAtMs`, medium speed, flat) and the scripted Opponent rally 100 Shots without the Rally ending
- [ ] The same seed and scripted Swings twice give an identical `RallyEvent` log
- [ ] Return Drill's P2-0 headless test still passes unchanged

**Done (you check)**: with `?mode=match` you can hold a Rally with the webcam against the scripted Opponent.

**Out of scope**: Opponent decisions and mistakes (P2-c), scoring (P2-e), Serves (P2-f1, P2-f2), the Opponent's figure (P2-d).

## P2-e Match rules

**Goal**: a pure, fully tested scoring state machine for a Game to 11 and an optional best-of-3 Match, driven by reporting who won each Rally.

**Owns**: `src/game/match.ts` and test.

**Depends on**: P2-0 (`Side`). Can run in parallel with P2-b; it doesn't touch the rally code.

**Contract**

```ts
export interface MatchConfig { pointsToWin: number; winBy: number; bestOf: number }   // 11, 2, 1 or 3
export interface MatchState {
  games: Record<Side, number>;
  points: Record<Side, number>;
  server: Side;
  servesLeft: number;                   // in the current server's turn
  gameFirstServer: Side;                // who served first in this Game
  phase: 'pre-serve' | 'rally' | 'game-over' | 'match-over';
  winner?: Side;
}
export function newMatch(cfg: MatchConfig, firstServer: Side): MatchState;
export function startRally(s: MatchState): MatchState;
export function cancelRally(s: MatchState): MatchState;      // a Let, or a Rally interrupted by lost tracking: back to pre-serve, same server, no Point
export function awardPoint(s: MatchState, to: Side, cfg: MatchConfig): MatchState;
export function nextGame(s: MatchState, cfg: MatchConfig): MatchState;
```

**Rules**

- A Game is won by the first to 11 Points with a lead of at least 2.
- The Serve passes every 2 Points; from 10–10, every Point.
- In best of 3, the side that served first in a Game receives first in the next.
- Functions are pure: they return new state and never mutate. Invalid calls (a Point during `pre-serve`, `startRally` after `match-over`) throw.
- The first server of a Match is chosen by the caller with the seeded `random` (P2-f1).

**Done (Claude checks)**

- [ ] Table-driven tests: 11–0, 11–9, 10–10 → 12–10, 10–10 → 11–11 → 13–11, deuce up to 20–20 → 22–20
- [ ] Serve rotation correct for every Point of a 0–0 to 11–9 Game and through a deuce
- [ ] `cancelRally` changes nothing but the phase
- [ ] Best of 3: first server alternates between Games; the Match ends at 2 Games
- [ ] Property test: 10,000 random Point sequences never reach an impossible state

**Out of scope**: Serve mechanics (P2-f1, P2-f2), UI (P2-h1, P2-h2).

## P2-c Opponent brain

**Goal**: an Opponent that picks a good Shot and then makes human-looking mistakes, more often against harder balls, at three Difficulties. Its mistakes give the player chances (a Pop-up to attack) rather than look like glitches, and Difficulty never changes during a Match.

**Owns**: `src/opponent/difficulty.ts`, `src/opponent/brain.ts`, their tests, `src/game/core.ts` (use the brain; expose `opponentPlan`), `src/main.ts` (`?difficulty=` flag only).

**Depends on**: P2-b.

**Contract**

```ts
export type Difficulty = 'novice' | 'intermediate' | 'expert';
export interface DifficultyParams {
  mistakeBase: number; mistakeSlope: number;   // mistake chance = mistakeBase + mistakeSlope · d
  popUpShare: number;                          // share of mistakes that are Pop-ups; the rest split evenly into Errors and Whiffs
  scatterM: number;                            // std dev of a good Shot's target, m
  minFlightS: number; maxFlightS: number;      // simulated s, never above OPPONENT_MAX_FLIGHT_S (1.1)
  maxSpinRevs: number;
  cornerAim: number;                           // 0..1 chance of aiming for a corner
  earlyBias: number;                           // 0..1 pull toward cross-court
}
export const DIFFICULTIES: Record<Difficulty, DifficultyParams>;
export function createBrain(params: DifficultyParams, solve?: ShotSolver): Opponent;
// core.ts: readonly opponentPlan: { incoming: Incoming; choice: ShotIntent | 'whiff' } | null
```

**Starting values** (guesses; P2-g2 tunes them)

| Parameter | Novice | Intermediate | Expert |
| --- | --- | --- | --- |
| `mistakeBase` | 0.15 | 0.07 | 0.02 |
| `mistakeSlope` | 0.35 | 0.25 | 0.15 |
| `popUpShare` | 0.6 | 0.4 | 0.2 |
| `scatterM` | 0.25 | 0.15 | 0.07 |
| `minFlightS` / `maxFlightS` | 0.85 / 1.1 | 0.7 / 1.1 | 0.5 / 1.0 |
| `maxSpinRevs` | 15 | 30 | 50 |
| `cornerAim` | 0.1 | 0.4 | 0.75 |
| `earlyBias` | 0.5 | 0.2 | 0.05 |

The 1.1 s cap is the same one Feeds have: a slower ball is a lob that lands short and bounces twice on the player's half. To slow a Difficulty further, lower `TIME_SCALE`, never raise the cap.

**Algorithm for `chooseShot`**

1. **Incoming difficulty** `d` in 0..1 from `incoming.strike`: speed against 12 m/s, |spin| against 50 rev/s, |x| against 0.76 m, weighted 0.5, 0.25, 0.25, clamped.
2. **Mistake?** If `random() < mistakeBase + mistakeSlope · d`:
   - with probability `popUpShare`, a **Pop-up**: target (0, 0.9 m), flight `OPPONENT_MAX_FLIGHT_S`, no spin;
   - otherwise half the time a **Whiff** (`'whiff'`) and half the time an **Error**: target 0.2–0.4 m past the player's end line or wide of a sideline, flight in range. ADR 0001: only the target is off.
3. **Good Shot**: a corner (x = ±0.6, z = 1.1 m) with probability `cornerAim`, else uniform over x ∈ [−0.6, 0.6], z ∈ [0.4, 1.2]. Add Gaussian scatter, then a cross-court pull of `earlyBias · 0.3 m` (x away from the strike's side). Clamp to the table with a 5 cm margin, so only Errors land out. Flight uniform in [`minFlightS`, `maxFlightS`]. Topspin with probability 0.75, else Backspin, magnitude uniform in [0, `maxSpinRevs`].
4. **Solve** from `contactPoint(strike.position)` with `solveShot`. A good Shot or Pop-up with no solution retries once 0.2 m closer to (0, 0.7), then falls back to (0, 0.7) with no spin. An Error goes through `solveReturn` so its target never moves.

**Done (Claude checks)**

- [ ] Each Difficulty, 10,000 synthetic `Incoming`s spread from easy to hard: mistake rate within ±2 points of the formula; Pop-up share within ±3 points
- [ ] Average flight time and target scatter strictly ordered Novice > Intermediate > Expert
- [ ] Every good Shot and Pop-up is solvable, and simulated, bounces exactly once on the player's half before `PLAYER_END_Z`; every Error lands off the table
- [ ] Same seed, same sequence
- [ ] Headless Rallies of the scripted player against each Difficulty end, and Expert Rallies are longer than Novice on average over 200 Rallies

**Out of scope**: movement and animation (P2-d), Serves (P2-f1), adaptive difficulty.

## P2-d Opponent body

**Goal**: a visible Opponent that moves to the ball and swings at the right moment, so its Shots look like they come from a player. ADR 0002: the body is cosmetic and never changes an outcome.

**Owns**: `src/opponent/motion.ts` and test, `src/render/opponent.ts`, `src/render/scene.ts` (add the figure, `syncOpponent(pose)`), `src/main.ts` (call `planBody` each frame from `core.opponentPlan`).

**Depends on**: P2-c. Can run in parallel with P2-f1.

**Contract**

```ts
export interface BodyParams { reactionS: number; maxSpeed: number; maxAccel: number; reach: number }
export const BODY_PARAMS: Record<Difficulty, BodyParams>;
// novice 0.25 s / 2.5 m/s; intermediate 0.18 s / 3 m/s; expert 0.12 s / 3.5 m/s; maxAccel 12 m/s², reach 0.7 m (guesses)
export interface BodyPose { x: number; lean: number; swingPhase: number; paddleTilt: number }
export interface BodyPlan { incoming: Incoming; choice: ShotIntent | 'whiff'; simSecondsSinceLaunch: number }
export function planBody(prev: BodyPose, plan: BodyPlan | null, dtSim: number, p: BodyParams): BodyPose;
```

**Behaviour** (all times simulated seconds)

- **Footwork**: `reactionS` after the incoming Shot's launch, slide sideways toward `strike.position.x` within `maxSpeed` and `maxAccel`. Between Shots, drift back to the centre.
- **Reach**: if it can't get within `reach` of the ball by the Ideal Time, it leans and stretches instead of teleporting.
- **Swing**: backswing from 0.25 s before the Ideal Time, contact pose at it, follow-through for 0.3 s. On a Whiff, the contact pose comes 0.15 s late, through empty air.
- **Paddle face**: closed for Topspin, open for Backspin, from the choice.
- **Look**: a simple low-poly figure (capsule body, sphere head, paddle) behind the far end, matching the current art.

**Done (Claude checks)**

- [ ] `planBody` never exceeds `maxSpeed` or `maxAccel` across 1,000 seeded Rallies
- [ ] For reachable balls, the paddle is within 5 cm of the strike position at the Ideal Time
- [ ] `core.ts` doesn't import `motion.ts`, so a headless Match is identical with or without the body

**Done (you check)**: at all three Difficulties, it looks like the Opponent really hits the ball.

**Out of scope**: character art, facial animation, any effect on outcomes.

## P2-f1 Opponent Serves and scoring

**Goal**: a scored Match. Every Rally starts with a legal Opponent Serve, and the core keeps the Match score from each Rally End.

**Owns**: `src/game/serve.ts` and test, `src/game/rally.ts` and test (Serve rules), `src/opponent/brain.ts` and test (`chooseServe`), `src/game/core.ts` and test (Rallies start from Serves; drives `match.ts`).

**Depends on**: P2-c and P2-e.

**Contract**

```ts
export interface ServeIntent { bounce1: TablePoint; target: TablePoint; flightTime: number; topspin: number; sidespin: number }
/** First bounce within 5 cm of bounce1, second within 10 cm of target; null if no solution. */
export function solveServe(from: Vec3, s: ServeIntent, solve?: ShotSolver): ShotSolution | null;
export type ServeResult = 'legal' | 'fault' | 'let';
// Opponent gains: chooseServe(random: () => number): ServeIntent
```

**Serve rules** (simplified, in `GLOSSARY.md`)

- A Serve must bounce first on the server's half, then on the receiver's half. Anything else is a **Fault**: the receiver wins the Point.
- A Serve that clips the net and then lands legally is a **Let**: `cancelRally`, serve again.
- After a legal Serve, the Rally goes on under P2-b's rules.

**Opponent Serve**: `bounce1` on its half (z in [−0.9, −0.3]), target on the player's half, closer to the corners with higher `cornerAim`, spin up to `maxSpinRevs` (Topspin or Backspin; the player answers it with Lift). Solve with a shooting method: `solveShot` to `bounce1`, simulate through the bounce, correct launch velocity and first-segment time until the second bounce is within 10 cm. The Opponent never Faults.

**Match wiring**: in Match mode the core holds a `MatchState` (first server from `random`), starts each Rally with an Opponent Serve, awards the Point from each Rally End or Fault, and calls `cancelRally` on a Let. Until P2-f2, the Opponent serves even when `MatchState.server` is the player. The score is logged to the console until P2-h1.

**Done (Claude checks)**

- [ ] 1,000 seeded Opponent Serves per Difficulty are all legal and clear the net
- [ ] Unit tests for Fault, Let and legal Serve outcomes, for a Serve from either end
- [ ] Headless Match between the scripted player and each Difficulty runs to `match-over` with a legal final score

**Done (you check)**: with `?mode=match` you can receive the Opponent's Serves and play a scored Game, reading the score from the console.

**Out of scope**: the player's Serve (P2-f2), any score display (P2-h1).

## P2-f2 Player Serve

**Goal**: the player serves from an **automatic toss**: after "3, 2, 1" the ball rises from the player's end and the player swings at it. The Serve now follows `MatchState.server`.

**Owns**: `src/game/serve.ts` and test, `src/game/shotResolver.ts` and test (Serve plan, toss Ideal Time), `src/game/core.ts` and test (player Serve turns), `src/game/constants.ts` (toss constants).

**Depends on**: P2-f1.

**Player Serve**

1. When the player serves: the "3, 2, 1" cue, then the **toss**: the ball appears 0.1 m behind the player's end line on the hitting-hand side (x = ±0.3 m), 0.1 m above the table, and rises about 0.4 m.
2. **Hit Window**: centred on the moment the falling ball passes 0.25 m above the table top, same width and Timing Offset as Returns.
3. **Shot**: `bounce1` on the player's own half, target on the Opponent's half, from the same timing/speed/Lift rules as `planReturn`, solved with `solveServe`. ADR 0001: a badly timed or over-hit Serve Faults only because its target moves long or wide.
4. **Missed toss** (no Swing, or one outside the Hit Window): the ball drops, the cue and toss restart, no Fault.

**Done (Claude checks)**

- [ ] A player Serve at timing 0 and medium speed is legal; one at the edge of the Hit Window with a fast Swing can Fault
- [ ] A missed toss restarts with no Point
- [ ] Headless Match: the Serve order follows `MatchState.server` for a whole Game, through a deuce

**Done (you check)**: serving with the webcam feels natural within a few tries.

**Out of scope**: the free-hand toss gesture (Later), Sidespin Serves, strict ITTF toss rules.

## P2-g2 Balance harness

**Goal**: tune the three Difficulties with thousands of simulated Matches before any human playtest.

**Owns**: `src/tools/simPlayer.ts` and test, `scripts/balance.ts`, `package.json` (script `balance`), `docs/balance-report.md`.

**Depends on**: P2-f2 and P2-g1.

**Contract**

```ts
export function createSimPlayer(model: PlayerModel, core: GameCore, random: () => number): SwingSource;
```

**Steps**

1. `SimPlayer` watches each `Incoming` toward the player (and its own Serve toss) and emits a `SwingEvent` at the Ideal Time plus Gaussian timing error, dropping Swings at `1 − detectRate`.
2. `npm run balance -- --matches 500` plays every Difficulty against every model and prints: Opponent win rate, average Rally length, average Points per Game, Opponent mistake rate.
3. `--sweep mistakeBase=0.05:0.25:0.05 --difficulty novice --model first-timer` grid-searches one parameter.

| Novice vs first-timer | 40% or less |
| Intermediate vs you | 40–60% |
